# Нефункциональные требования (НФТ)

Данный документ фиксирует архитектурные, качественные и эксплуатационные требования, не связанные с бизнес-логикой визуализации. Является самостоятельным дополнением к Техническому Заданию.

---

## 1. Архитектурные и технологические ограничения

| Требование             | Описание                                                                                                                                                                                                         |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Zero Dependencies**  | Запрещено использование любых сторонних библиотек, фреймворков или пакетов (`npm`, `yarn`, `pnpm`). Исключение: базовые браузерные API.                                                                          |
| **No Build System**    | Запрещены сборщики (`webpack`, `vite`, `rollup`, `esbuild`), транспиляторы (`babel`, `typescript`) и таск-раннеры. Код выполняется нативно в браузере.                                                           |
| **Module System**      | Использование нативных ES Modules (`<script type="module">`). Файлы организуются в плоскую или вложенную директорию `src/`. Импорт/экспорт через `import`/`export`.                                              |
| **Target Environment** | Современные десктопные браузеры: Chrome 90+, Firefox 90+, Edge 90+, Safari 14+. Мобильные и планшеты не поддерживаются.                                                                                          |
| **Fixed Resolution**   | Верстка оптимизирована под `1920x1080`. Адаптивные медиа-запросы, относительные единицы (`vh`, `vw`, `%`) используются только для внутреннего масштабирования компонентов, а не для адаптации под другие экраны. |
| **Network Policy**     | После загрузки `index.html` приложение работает полностью офлайн. Запрещены любые сетевые запросы (`fetch`, `XMLHttpRequest`, `WebSocket`).                                                                      |

## 2. Требования к коду и качеству

| Требование           | Описание                                                                                                                                                                            |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Язык**             | Vanilla JavaScript (ES2020+). Строгий режим (`"use strict"`).                                                                                                                       |
| **Стиль именования** | `camelCase` — переменные, функции, файлы.<br>`PascalCase` — классы, компоненты UI.<br>`UPPER_SNAKE_CASE` — константы, конфигурации.<br>`kebab-case` — CSS-классы.                   |
| **Чистые функции**   | Все парсеры, нормализаторы и расчётчики макетов должны быть чистыми функциями (без мутации входных данных, без побочных эффектов).                                                  |
| **DOM-манипуляции**  | Запрещён `innerHTML` для динамических данных. Использовать `textContent`, `appendChild`, `DocumentFragment` или `createSVGElement`.                                                 |
| **Конфигурация**     | Все настраиваемые параметры (fallback-цепочки, лимиты, флаги отладки) вынесены в отдельные объекты/файлы в `src/config/`. Жёстко захардкоженные значения в бизнес-логике запрещены. |
| **CSS**              | Использование CSS-переменных (`:root`) для темизации. Запрет на инлайн-стили в JS, кроме критичных для расчёта позиций (`left`, `top`, `width`, `height`).                          |

## 3. Логирование и отладка

| Требование              | Описание                                                                                                                                                                       |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Логгер**              | Реализуется лёгкая утилита `src/utils/Logger.js`. Зависимостей нет. Уровни: `DEBUG`, `INFO`, `WARN`, `ERROR`.                                                                  |
| **Формат**              | `[LEVEL] [Module] Сообщение` (например: `[DEBUG] [ScopeExtractor] Found SpanId in Scopes array`).                                                                              |
| **Флаг отладки**        | Глобальная константа `const APP_DEBUG = false;` в `src/config/app.js`. При `true` включаются `DEBUG`-логи и расширенные проверки типов. В релизе `false`.                      |
| **Performance Logging** | Критичные этапы парсинга и рендеринга оборачиваются в `console.time()`/`console.timeEnd()`. Вывод в консоль при `APP_DEBUG = true`.                                            |
| **Error Boundary**      | Глобальный перехватчик `window.onerror` и `unhandledrejection`. Отображает пользовательский баннер с кодом ошибки, детали пишет в консоль. Приложение не падает в белый экран. |
| **Запреты**             | Запрещены `alert()`, `prompt()`, `confirm()`. Запрещены `console.log()` без уровня в продакшен-коде.                                                                           |

## 5. Производительность и управление ресурсами

| Требование          | Описание                                                                                                                                                                                                    |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Memory Limit**    | Внутреннее хранение распарсенных данных не должно превышать `150 МБ` для файлов до `50 МБ`. Сырой JSON-текст освобождается сразу после парсинга (`raw = null`).                                             |
| **Rendering Limit** | Вертикальная виртуализация включается автоматически при `>100` элементов в списке/дереве. Горизонтальный скролл таймлайна рендерит весь SVG, но использует `transform`/`viewBox` для аппаратного ускорения. |
| **Main Thread**     | Запрещены блокирующие синхронные операции >50 мс. Тяжёлые вычисления разбиваются на чанки через `requestAnimationFrame` или `setTimeout(..., 0)`.                                                           |
| **DOM Nodes**       | Максимальное количество одновременных DOM/SVG-элементов в viewport: `~2000`. При превышении — принудительная виртуализация.                                                                                 |
| **FPS Target**      | Интерактивные операции (скролл, зум, hover) должны поддерживать `≥50 FPS` на целевом разрешении.                                                                                                            |

## 6. Безопасность и конфиденциальность

| Требование           | Описание                                                                                                                                                  |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Client-Side Only** | Данные не покидают браузер. Нет отправки телеметрии, аналитики или логов на внешние серверы.                                                              |
| **Storage**          | Версия 1.0 не использует `localStorage`, `sessionStorage`, `IndexedDB`, `Cookies`. Все данные живут в памяти до перезагрузки страницы.                    |
| **Sanitization**     | Любой текст из лога, попадающий в DOM, вставляется через `textContent` или `createTextNode`. Экранирование HTML-сущностей обязательно.                    |
| **File Access**      | Чтение файлов строго через `<input type="file">` или Drag&Drop API. Нет доступа к файловой системе за пределами выбранного файла.                         |
| **Clipboard Access** | Чтение из буфера обмена только через `navigator.clipboard.readText()` по жесту пользователя. Данные не сохраняются в localStorage/sessionStorage/Cookies. |

## 7. Обработка ошибок и устойчивость

| Требование               | Описание                                                                                                                                                                          |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Graceful Degradation** | Приложение не должно падать при отсутствии обязательных полей. Используются fallback-значения, пустые состояния, информативные баннеры.                                           |
| **Validation**           | Каждый этап пайплайна (Load → Parse → Normalize → Group → Render) имеет блок `try/catch`. Ошибка на любом этапе не прерывает работу всего приложения, а изолируется и логируется. |
| **Malformed Input**      | При невалидном JSON или битой структуре выводится модальное окно с указанием строки/символа ошибки (если возможно) и предложением проверить файл.                                 |
| **State Recovery**       | При критической ошибке рендеринга интерфейс возвращается в состояние "Загрузка файла". Кеш или состояние не сохраняются.                                                          |

## ✅ Чек-лист приёмки НФТ

- [ ] В проекте отсутствует `package.json`, `node_modules`, конфиги сборщиков
- [ ] Используются только нативные ES Modules и CSS
- [ ] Верстка фиксирована под 1920x1080, нет адаптивных breakpoint'ов
- [ ] Реализован `Logger.js` с уровнями и флагом `APP_DEBUG`
- [ ] Все публичные функции покрыты JSDoc
- [ ] Сложная логика снабжена поясняющими комментариями
- [ ] `README.md`, `ARCHITECTURE.md`, `EXTENSION_GUIDE.md` созданы и заполнены
- [ ] Сырой JSON очищается из памяти после парсинга
- [ ] Виртуализация активируется при `>100` элементов
- [ ] Нет блокирующих операций >50 мс в main thread
- [ ] Нет `fetch`/сетевых запросов после загрузки страницы
- [ ] Весь динамический текст рендерится через `textContent`
- [ ] Глобальный перехватчик ошибок отображает UI-баннер и логирует в консоль
- [ ] Приложение не падает при отсутствии полей в логе (тест на пустом/битом файле)
- [ ] ClipboardReader использует только нативный Clipboard API, без зависимостей
- [ ] Данные из буфера не сохраняются в постоянное хранилище
- [ ] Все ошибки ClipboardReader отображаются через StatusBanner
