# Техническое Задание

## 1. Карта извлечения полей

Все поля опциональны. При отсутствии всех fallback-полей концепт помечается как отсутствующий. Применяется правило первого непустого значения.

| Концепт       | Приоритетные поля (Fallback Chain)                               | Тип / Парсинг | Поведение при отсутствии                                                                                                                                                       |
| ------------- | ---------------------------------------------------------------- | ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **TraceId**   | TraceId → TraceIdOld → TraceIdentifier → Scopes (парсинг строки) | Строка        | Запись попадает в группу UNCATEGORIZED                                                                                                                                         |
| **SpanId**    | SpanId → Scopes (парсинг строки)                                 | Строка        | Помечается как отсутствующий. Активирует режим Flat или Shifted                                                                                                                |
| **ParentId**  | ParentId → Scopes (парсинг строки)                               | Строка        | Помечается как отсутствующий. Спан считается корневым                                                                                                                          |
| **Duration**  | ElapsedMilliseconds → elapsed                                    | Число         | ElapsedMilliseconds читается как float. elapsed парсится из строки: поддержка форматов с разделителями, единицами измерения и временным интервалом. При неудачном парсинге → 0 |
| **Timestamp** | timestamp → LogDate → CreatedOn                                  | Дата/Время    | При отсутствии всех полей → запись помещается в начало шкалы с меткой отсутствия времени. Не участвует в расчёте границ шкалы                                                  |
| **StageName** | ActionName → Category → IntegrationName → Exception → Message    | Строка        | Первое непустое значение. Максимальная длина: 200 символов с добавлением многоточия. Полный текст сохраняется в сыром объекте для детального просмотра                         |
| **ErrorFlag** | LogLevel ∈ {Error, Fatal, Critical} ИЛИ наличие поля Exception   | Логический    | Визуальная пометка красным цветом                                                                                                                                              |

## 2. Алгоритм парсинга Scopes

Поле Scopes опционально. Если присутствует, представляет собой массив строк.

1. Проверка на существование и тип массива. При отсутствии или некорректном типе → пропуск.
2. Последовательный проход по каждому элементу массива.
3. Разбиение строки по запятым и пробелам.
4. Поиск фрагмента, начинающегося с целевого ключа (например, SpanId:, TraceId:, ParentId:).
5. Извлечение значения, следующего за двоеточием, до ближайшего пробела, запятой или конца строки.
6. При успешном извлечении → возврат значения. При неудаче → возврат пустого значения.

## 3. Уровни деградации и отображения

| Уровень                | Условия                                              | Режим отрисовки                                                                                                                                                                                                                                                                                                                                                               | Сообщение в UI                                                        |
| ---------------------- | ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| 🟢 **Full Trace**      | Все записи имеют SpanId и корректную связку ParentId | Waterfall-дерево с иерархическими отступами по уровням вложенности                                                                                                                                                                                                                                                                                                            | ✅ Полный трейс с иерархией спанов                                    |
| 🟡 **Flat Trace**      | SpanId отсутствует у всех записей трейса             | Хронологический список: каждая запись на отдельной строке, ось Y соответствует индексу, ось X соответствует времени. Без иерархических отступов                                                                                                                                                                                                                               | ⚠️ SpanId не найден. Отображение хронологически                       |
| 🟠 **Shifted / Mixed** | SpanId/ParentId присутствуют частично                | Гибридный рендеринг: записи без SpanId встраиваются внутрь спана, чей временной интервал покрывает метку времени записи. При множественном совпадении выбирается наиболее вложенный спан. При отсутствии совпадения → привязка к последнему хронологическому спану. Визуально выделяются отступом, пунктирной рамкой и серым фоном. Сортировка внутри спана строго по времени | ⚠️ Структура неоднородна. Записи без SpanId встроены в последний спан |
| 🔴 **UNCATEGORIZED**   | Отсутствуют все идентификаторы для группировки       | Табличное представление с фиксированными колонками: Timestamp, LogLevel, Message, ElapsedMilliseconds, Scopes. Кнопка выгрузки массива в JSON-файл                                                                                                                                                                                                                            | ❌ Отображение сырых данных (без TraceId)                             |

## 4. Архитектурные и технологические ограничения

- **Целевое разрешение:** 1920x1080. Верстка фиксированная, оптимизирована под десктопные мониторы. Адаптивность не реализуется.
- **Сборка:** Отсутствует. Используется нативная модульная система или классические скрипты.
- **Зависимости:** Минимальные. Рендеринг спанов реализуется на нативных технологиях.
- **Запуск:** Локальный HTTP-сервер. Прямое открытие файла ограничено политиками безопасности браузеров.
- **Безопасность:** Полностью клиентская обработка. Файлы читаются в память браузера. Сетевые запросы отсутствуют.
- **Производительность:** Вертикальная виртуализация списков при превышении порога элементов. Горизонтальная временная шкала рендерится полностью, скролл осуществляется через нативные механизмы контейнера. Блокировка основного потока не допускается.
