# 📜 Требования к тестированию (ТЗ на тесты)

## 1. Цели и принципы

| Принцип                        | Описание                                                                                                                          |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| **Zero Impact on Production**  | Тесты не должны влиять на размер, производительность или зависимости продакшен-сборки. Запускаются только в Node.js / dev-режиме. |
| **Детерминированность**        | Все тесты должны быть воспроизводимы, без зависимости от времени выполнения, порядка файлов или случайных данных.                 |
| **Покрытие критических путей** | Приоритет: парсеры, нормализаторы, HybridLayoutEngine, TraceClassifier. DOM/SVG-рендеринг тестируется визуально/ручно.            |
| **Быстрый фидбек**             | Запуск полного набора тестов ≤ 5 секунд на локальной машине.                                                                      |

## 2. Уровни тестирования и инструменты

| Уровень              | Что тестируем                                                              | Инструмент (соответствие НФТ)                                    | Где запускается            |
| -------------------- | -------------------------------------------------------------------------- | ---------------------------------------------------------------- | -------------------------- |
| **Unit**             | `ScopeExtractor`, `ElapsedParser`, `DataNormalizer`, `TraceClassifier`     | Native Node.js `assert` + кастомный раннер без зависимостей      | `npm run test:unit`        |
| **Integration**      | Полный пайплайн: JSON → `OpenSourceExtractor` → нормализация → группировка | Загруз реальных `samples/*.json`, проверка структуры на выходе   | `npm run test:integration` |
| **Regression/Smoke** | Визуальная корректность Waterfall/Shifted/UNCATEGORIZED, экспорт JSON      | Ручная проверка + автосравнение хэшей выходных структур          | `npm run test:smoke`       |
| **Performance**      | Память при >1000 спанов, FPS скролла, время парсинга                       | `process.memoryUsage()`, `console.time`, ручной замер в DevTools | `npm run test:perf`        |

## 3. Ключевые тестовые сценарии (Mapping к ТЗ)

| Модуль                       | Сценарий                                                                                | Ожидаемый результат                                                    |
| ---------------------------- | --------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| `ScopeExtractor`             | Парсинг строки `"SpanId:abc, TraceId:def, ParentId:123"`                                | Возвращает `{ spanId: "abc", traceId: "def", parentId: "123" }`        |
| `ScopeExtractor`             | `Scopes = undefined` или `[]`                                                           | Возвращает `null` для всех полей, без ошибок                           |
| `ElapsedParser`              | `"1,234 ms"`, `"00:00:01.500"`, `"2"`, `"1.5s"`                                         | Возвращает `1234`, `1500`, `2`, `1500` соответственно                  |
| `DataNormalizer`             | `StageName` из `Exception` длиной 300 символов                                          | Обрезка до 200 символов + `...`, полный текст в `rawData`              |
| `HybridLayoutEngine`         | Orphan-запись с `timestamp` внутри интервала спана A, но хронологически ближе к спану B | Привязка к спану A (попадание в `[startTime, endTime]`)                |
| `HybridLayoutEngine`         | Спан с `durationMs = 0`                                                                 | `endTime` = `startTime` следующего спана с `SpanId` или `maxTraceTime` |
| `TraceGrouper`               | Записи без `TraceId` и fallback-идентификаторов                                         | Попадание в массив `orphanLogs`, корректный экспорт в JSON             |
| `FileLoader/ClipboardReader` | Невалидный JSON, пустой буфер, битая структура `hits.hits`                              | Ошибка в UI, лог `ERROR`, приложение не падает                         |
| `Memory Management`          | Загрузка файла 50 МБ, повторная загрузка другого файла                                  | `rawText` зануляется, `heapUsed` не растёт линейно                     |

## 4. Структура тестов в репозитории

```
trace-viz/
├── __tests__/
│   ├── unit/
│   │   ├── scope-extractor.test.js
│   │   ├── elapsed-parser.test.js
│   │   └── data-normalizer.test.js
│   ├── integration/
│   │   ├── pipeline-full-trace.test.js
│   │   └── pipeline-shifted-trace.test.js
│   ── utils/
│       └── test-runner.js  # Кастомный раннер (0 зависимостей)
├── samples/                # Тестовые данные (уже есть)
└── package.json            # Скрипты запуска тестов
```

## 5. Критерии приёмки тестовой инфраструктуры

- [ ] Тесты запускаются командой `npm test` без установки сторонних пакетов
- [ ] Покрытие критических модулей (парсеры, процессоры) ≥ 80% строк
- [ ] Все edge-кейсы из ТЗ (Shifted, Flat, UNCATEGORIZED, Scopes, elapsed) покрыты
- [ ] Тесты не модифицируют исходные файлы `src/`, работают с копиями или моками
- [ ] При падении теста выводится понятное сообщение с указанием файла и строки
- [ ] Интеграционные тесты используют файлы из `samples/` как эталонные данные

## 6. Интеграция в workflow (npm scripts)

Добавьте в `package.json`:

```json
{
	"scripts": {
		"test": "npm run test:unit && npm run test:integration",
		"test:unit": "node __tests__/utils/test-runner.js __tests__/unit/",
		"test:integration": "node __tests__/utils/test-runner.js __tests__/integration/",
		"test:smoke": "echo ' Запустите npm run dev и проверьте samples/ вручную'",
		"test:perf": "node __tests__/utils/perf-check.js",
		"prepush": "npm test"
	}
}
```

## 7. Практические шаги для старта

1. Создать ветку: `git checkout -b feature/testing-infrastructure`
2. Добавить `__tests__/utils/test-runner.js` (простой обход папки, запуск через `import()`, сбор/assert)
3. Написать первые 3 unit-теста (`ScopeExtractor`, `ElapsedParser`, `DataNormalizer`)
4. Добавить интеграционный тест на `sample_full_trace.json` и `sample_mixed_shifted.json`
5. Запустить `npm test`, убедиться в зелёном статусе
6. Залить в `develop` через PR с описанием покрытия
