# Техническое задание: Epic 9 — Интерфейсный переключатель режима отладки

## Цель эпика

Добавить в интерфейс визуальный переключатель, который управляет отображением панели журналов (`#log-table`) и синхронизирует своё состояние с конфигурацией `APP_DEBUG` из `src/config/app.js`. При выключенном переключателе логи не рендерятся в UI, но продолжают записываться в консоль браузера для разработчика.

---

## 2. Технические требования

### 2.1 Структура HTML (добавление в index.html)

В блок `.log-table__header`, после кнопки `#clear-logs`:

```html
<label class="debug-toggle" title="Показывать логи в интерфейсе">
	<input
		type="checkbox"
		id="debug-toggle-input"
		class="debug-toggle__input"
		role="switch"
		aria-checked="false"
		aria-label="Показывать логи в интерфейсе"
	/>
	<span class="debug-toggle__slider"></span>
	<span class="debug-toggle__label">Debug UI</span>
</label>
```

### 2.2 Логика работы переключателя

1. **Инициализация**:
    - Чтение `APP_DEBUG` из `src/config/app.js`.
    - Чтение сохранённого значения из `localStorage` (ключ `trace-viz:debug-enabled`).
    - Приоритет: `localStorage` > конфиг.
    - Установка состояния `<input>` и видимости `#log-table`.
2. **Обработчик `change`**:
    - Вызов `setDebugEnabled(newValue)` из `app.js`.
    - Сохранение `newValue` в `localStorage`.
    - Показ/скрытие `#log-table` через `element.style.display`.
    - При включении — отрисовка накопленных логов (если буферизировались).
3. **Подписка на `debug:changed`**:
    - `Logger` и другие модули могут реагировать на изменение флага без прямого доступа к переключателю.

### 2.3 Поведение Logger

| Состояние `APP_DEBUG` | Поведение `Logger.logToUI()`                                   |
| --------------------- | -------------------------------------------------------------- |
| `true`                | Запись рендерится в `#log-container` + пишется в `console`     |
| `false`               | Запись пишется только в `console`, рендеринг в UI пропускается |

### 2.4 Доступность (a11y)

- `<input>` имеет `id` и связан с `<label>` через `for`.
- Элемент управляется с клавиатуры: `Tab` → фокус, `Space`/`Enter` → переключение.
- ARIA-атрибуты: `role="switch"`, `aria-checked`, `aria-label`.
- Визуальный фокус отображается через `:focus` в CSS.

## 4. Критерии приёмки

- [ ] Переключатель отображается в заголовке панели журналов, справа от кнопки «Очистить»
- [ ] Переключатель имеет корректные стили, анимацию и тултип при наведении
- [ ] При загрузке страницы состояние переключателя соответствует `localStorage` или `APP_DEBUG` из конфига
- [ ] Переключение мгновенно скрывает/показывает панель `#log-table` без перезагрузки
- [ ] При выключенном переключателе новые логи не рендерятся в UI, но видны в консоли браузера
- [ ] Состояние сохраняется между перезагрузками страницы (ключ `trace-viz:debug-enabled`)
- [ ] Переключатель доступен с клавиатуры и скринридера (ARIA, фокус)
- [ ] Изменение состояния через код (`setDebugEnabled(true)`) отражается в UI
- [ ] Нет манипуляций с DOM при выключенном переключателе (проверка через DevTools → Elements)

## 5. Интеграция с текущей архитектурой

```
index.html (добавление #debug-toggle-input в .log-table__header)
   → src/ui/DebugToggle.js (инициализация, обработчик change, localStorage)
   → src/config/app.js (экспорт setDebugEnabled, событие debug:changed)
   → src/utils/Logger.js (проверка APP_DEBUG перед рендером в UI)
   → style.css (стили переключателя)
   → src/main.js (инициализация компонента при старте)
```

**Безопасность:** Переключатель не влияет на безопасность приложения — он только управляет видимостью логов в интерфейсе. Все данные остаются на клиенте.

**Производительность:** При выключенном режиме снижаются манипуляции с DOM (не добавляются элементы логов), что полезно при анализе крупных трейсов с частым логированием.
