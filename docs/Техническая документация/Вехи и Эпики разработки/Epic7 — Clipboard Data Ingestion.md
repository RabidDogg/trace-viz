# Техническое задание: Epic 7 — Clipboard Data Ingestion

## Цель эпика
Реализовать возможность загрузки логов напрямую из системного буфера обмена через нажатие кнопки, минуя текстовые поля ввода и горячие клавиши. Данные из буфера должны проходить через тот же пайплайн парсинга и нормализации, что и файлы.

---

## 1. Задачи реализации

| Задача | Артефакт | Критерий приёмки |
|--------|----------|------------------|
| 7.1 UI-элемент «Загрузить из буфера» | `index.html`, `style.css` | Кнопка с текстом «📋 Загрузить из буфера обмена» расположена рядом с кнопкой «Загрузить файл». Стилизация соответствует общему дизайну. При клике кнопка меняет состояние на «Загрузка...» и блокируется до завершения чтения. |
| 7.2 Модуль чтения буфера | `src/io/ClipboardReader.js` | Класс использует `navigator.clipboard.readText()`. Реализует асинхронное чтение. Обрабатывает случаи отсутствия поддержки API или отказа в правах доступа. |

| 7.4 Обработка ошибок и UX | `src/ui/StatusBanner.js`, `src/utils/Logger.js` | При пустом буфере, невалидном JSON или ошибке прав доступа выводится информативный баннер. В лог пишется уровень `ERROR`. Приложение возвращается в состояние ожидания данных, не зависая. |
| ✅ **Acceptance** | Клик по кнопке успешно загружает JSON из буфера, строит график или таблицу (UNCATEGORIZED) аналогично загрузке файла. |

## 2. Технические требования

### 2.1 Использование Browser API
*   **Метод:** `navigator.clipboard.readText()`.
*   **Secure Context:** Функционал доступен только в безопасном контексте (`https://` или `http://localhost`). Доступ через протокол `file://` (локальный файл) будет ограничен браузером и должен обрабатываться как ошибка с пояснением пользователю.
*   **User Gesture:** Запрос к буферу должен быть инициирован строго в обработчике события `click` на кнопке. Автозагрузка при открытии страницы запрещена.

### 2.2 Валидация данных
1.  **Пустой буфер:** Если возвращенная строка пустая или содержит только пробелы → Ошибка «Буфер обмена пуст».
2.  **JSON Parse:** Попытка выполнить `JSON.parse()`. При ошибке синтаксиса → Ошибка «Невалидный формат данных в буфере».
3.  **Структура:** Проверка наличия массива логов или объекта `hits.hits`. Если структура не распознана → Ошибка «Формат данных не соответствует OpenSearch JSON».

### 2.3 Логирование
*   `[INFO] [ClipboardReader] Start reading from clipboard.`
*   `[ERROR] [ClipboardReader] Access denied or API not supported.`
*   `[ERROR] [DataLoader] Failed to parse JSON from clipboard.`

## 3. Пользовательский сценарий (UX)

1.  Пользователь копирует JSON-ответ из OpenSearch (или другого источника) в буфер обмена.
2.  В интерфейсе визуализатора пользователь нажимает кнопку **«📋 Загрузить из буфера обмена»**.
3.  **Система:**
    *   Меняет текст кнопки на «Чтение...».
    *   Запрашивает данные у браузера.
    *   **Успех:** Скрывает кнопку чтения, отображает баннер «Данные успешно загружены», запускает парсинг и рендеринг (Waterfall или таблица).
    *   **Ошибка:** Возвращает текст кнопки, отображает красный баннер с описанием проблемы (например, «Ошибка: не удалось прочитать буфер обмена»).

---

## 4. Ограничения и безопасность
*   **Изоляция:** Данные из буфера не сохраняются ни в `localStorage`, ни в `sessionStorage`, ни в Cookies. Они хранятся только в оперативной памяти до перезагрузки страницы.
*   **Sanitization:** При отображении статуса ошибок или данных из буфера в DOM используется `textContent` для предотвращения XSS-атак.
*   **Без зависимостей:** Используется только нативный API браузера.
